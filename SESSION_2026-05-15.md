## Bugs Fixed (in order)

### Bug 1 — `DataCollatorForCompletionOnlyLM` ImportError
**Error:**
```
ImportError: cannot import name 'DataCollatorForCompletionOnlyLM' from 'trl'
```
**Root cause:** TRL 1.4.0 removed this class from both `trl` and `trl.trainer`. It no longer exists anywhere in the installed version.

**Fix:** Dropped TRL entirely for the data collation step. Replaced with a custom `MaskingCollator` dataclass and switched from `SFTTrainer` to the standard HuggingFace `Trainer`.

---

### Bug 2 — 0 Unmasked Tokens (loss masking broken)
**Symptom:** `Sample 0: 768 tokens, 0 unmasked (assistant response tokens)`

**Root cause:** Original approach searched for the response template (`<|assistant|>`) by encoding it in isolation and matching token IDs in the full sequence. The Nemotron tokenizer encodes `<|assistant|>` to 6 character-level tokens in isolation, but differently in context — so the subsequence never matched.

**Fix:** Tokenize the full prompt prefix (everything up to and including `<|assistant|>\n`) separately, use its length as the mask boundary. This is context-independent and always correct.

**Verified:** `Sample 0: 512 total tokens, 424 unmasked` — 424 tokens are the assistant response (correct).

---

### Bug 3 — `Trainer.__init__()` unexpected keyword argument `tokenizer`
**Error:**
```
TypeError: Trainer.__init__() got an unexpected keyword argument 'tokenizer'
```
**Root cause:** transformers 5.7.0 removed `tokenizer=` from `Trainer.__init__()`.

**Fix:** Removed `tokenizer=tokenizer` from the `Trainer` constructor. The custom `MaskingCollator` handles padding directly so the tokenizer is not needed by the Trainer.

---

### Bug 4 — CUDA OOM on Backward Pass (seq_len=512, BF16)
**Error:**
```
torch.OutOfMemoryError: CUDA out of memory. Tried to allocate 6.00 GiB.
GPU 0 has a total capacity of 22.03 GiB of which 4.28 GiB is free.
```
**Root cause:** The Mamba SSM `G_intermediate` tensor during the backward pass scales with sequence length and allocates ~6 GB at seq_len=512. With the full BF16 model using ~8 GB for weights, only ~4 GB remained — not enough.

**Fix:** Switched to **QLoRA** (4-bit NF4 quantized base model via `BitsAndBytesConfig`). This reduces model weight memory from ~8 GB to ~2 GB, freeing ~6 GB for the backward pass.

```python
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
)
model = AutoModelForCausalLM.from_pretrained(MODEL_ID, quantization_config=bnb_config, device_map="auto")
model = prepare_model_for_kbit_training(model, use_gradient_checkpointing=True)
```

## Key Lessons Learned
- **TRL 1.4.0 is a breaking change**: `DataCollatorForCompletionOnlyLM`, `SFTTrainer` API (`dataset_text_field`, `max_seq_length`), all changed. Use standard `Trainer` for version stability.
- **Mamba SSM training limit**: `MAX_SEQ_LEN <= 512` is required for both inference AND training on 24GB L4. 768 OOMs on backward.
- **QLoRA is necessary**: BF16 full precision leaves insufficient VRAM for Mamba's backward pass at any practical sequence length. Always use 4-bit for training this model.
- **Token masking via prefix length**: More reliable than template token-ID search for models with context-dependent special token encoding.
- **SSH exit 128 from plink ≠ command failed**: The remote `nohup` command often ran successfully even when plink returned exit code 128 (connection dropped before returning output).
